# Selective Quality Profiles

These are starting lenses, not exhaustive standards or automatic requirements. Load only the relevant profile. Prefer approved source material, the existing design system, authoritative platform documentation, and available specialist skills. Verify changing platform rules from current primary sources when material; do not invent requirements or claim certification.

For a custom profile record: use-when, required outcome, applicable checks, evidence, common overreach, and stop condition. No new user-facing skill is required.

## Interfaces and photo/content viewers

Use for visual and interactive products. Check the intended journey, navigation, hierarchy, readable content, consistent components, target viewports, and relevant keyboard/touch/accessibility behavior. For native mobile, consult the actual platform guidance and existing patterns; a generic web layout is not proof of native quality.

For a photo viewer, relevant checks may include differing aspect ratios, loading/empty/broken-image states, scrolling under intended conditions, and preservation of navigation state. Use rendered and interactive evidence for those claims. Data privacy and public access depend on the actual source and authorization.

Do not automatically add accounts, comments, analytics, administration consoles, or a backend. Stop at required flows and quality, not at an isolated attractive screen or an endless redesign.

## Software and data tools

Use for implemented behavior or data transformations. Check representative inputs/outputs, invalid input, error recovery, data preservation, rerun behavior, and relevant security/compatibility constraints. Prefer deterministic tests and source reconciliation; run broader checks only for plausible impact.

Use safe fixtures, temporary outputs, and explicitly authorized environments. Never use destructive production tests as routine validation. Avoid new frameworks, migrations, dependencies, or infrastructure unless needed and authorized.

When the recipient must operate the tool, include a minimal runnable example and clear failure signals. A successful build is not evidence that data transformation or the intended workflow is correct.

## Documents, analysis, and operational handoff

Use for reports, spreadsheets, instructions, and processes. Check source provenance, claims, calculations where applicable, audience fit, required sections, actual rendered readability, and a representative use case. Keep material uncertainty and required expert review explicit.

Preserve source terminology and approved content over decorative sections. Test the handoff with an agent walkthrough when possible, labeling it accurately. Preparation is not distribution; a proposed process is not an applied operational change.

## Video, audio, and communication

Use for time-based or communication artifacts. Check message comprehension, required copy/languages, readable text, pacing, picture/sound alignment, intelligibility, channel/format constraints, and coherent assets. Inspect the actual rendered output with available viewing/listening tools; source code or a storyboard cannot establish playback quality.

Preserve sources, attribution, rights assumptions, and publication boundaries. Do not infer conversion, retention, persuasion, or audience response from polish alone. Stop at the contracted package and quality, with unmeasured effects labeled.
