# C2O Execute

Deliver the approved outcome with the smallest coherent change, not a smaller outcome.

When implementation exposes an unsupported material premise or a missing professional prerequisite, use [expertise-discovery.md](../c2o-work/references/expertise-discovery.md) to inspect the evidence and reopen only affected decisions. A named technique is not proof it solves the problem, but do not replace an explicit method or accepted architecture without applicable delegated authority or agreement. Continue safe independent authorized work; preserve requirements, existing changes, and the review-only boundary. Do not conduct a new strategy interview for a settled bounded change.

## Execute

1. Load applicable repository instructions, inspect the real execution path and working tree, and preserve unrelated user changes.
2. Recover required deliverables, acceptance, completion level, approved design, non-goals, and authorization. Resolve only ambiguity that changes the implementation. Do not lower the quality target or replace a full request with a demo.
3. Use existing project patterns and relevant specialist skills. Consult [quality-profiles.md](../c2o-work/references/quality-profiles.md) only for applicable checks; do not invent dependencies or infrastructure.
4. Implement a coherent delivery slice. For repeated UI or systems, prove a representative quality slice before expanding, then continue through all committed slices.
5. Follow [quality-loop.md](../c2o-work/references/quality-loop.md): run, render, or interact with the actual result using available tools; identify the highest-impact material gap; repair within the same authorization; recheck affected criteria and regressions.
6. Validate narrowly first and broaden only when relevant. Missing tools or credentials are limitations, not passing tests. Never silently install, spend, deploy, or widen access to obtain evidence.
7. Inspect the diff for scope expansion, missing error paths, security regressions, broken quality consistency, and unverified assumptions.

Do not opportunistically refactor adjacent code. Stop before destructive actions, irreversible migrations, production writes, meaningful scope changes, or decisions with substantially different user outcomes. An existing approval of one action does not authorize a new external boundary.

Avoid repair loops without new evidence. Preserve completed work and report the specific blocker or remaining required gaps. A completed slice is not the whole task when other deliverables remain.

## Finish

Report behavior changed, required-deliverable coverage, files/artifacts, actual checks and evidence, acceptance status, and remaining limitations. Keep task completion separate from verification and deployment state. Never describe an unrun check as passing or source inspection as proof of interactive behavior.
